# 图片标签命名系统

一款基于 Python + tkinter 的本地图片批量命名工具。把「看图起名」变成「贴标签拖拽」，最终一键落成 Windows 上真实的文件名。

> 适用场景：图纸整理、素材归档、扫描件命名等需要**批量、可预期、统一风格**命名的场合。

---

## 功能特性

| 能力 | 说明 |
| --- | --- |
| 三栏布局 | 左侧文件树 / 中间标签工作区 / 右侧标签仓库，与资源管理器操作习惯一致 |
| 标签仓库 | 标签只记录**图片绝对路径 + 备注**，全局共享，不复制图片 |
| 5 套互斥预设 | 每套预设独立保存自己的分组与顺序，切换秒回，互不干扰 |
| 拖拽编排 | 标签可在仓库与组之间自由拖拽；组内可调顺序；组标题可拖动排序；跨组自动移除源位置 |
| 实时命名预览 | 单击标签即选中，底部立即显示拼接结果，所见即所得 |
| 一键命名 | 真实重命名磁盘文件，多文件自动追加 ` (2)`、` (3)` 编号 |
| 路径同步 | 已入库图片被重命名后，标签记录的路径自动跟随，不会变成「图片不存在」 |
| 图片预览 | 双击任意标签打开独立预览窗：滚轮以光标为中心缩放、按住左键拖动平移、适应窗口 / 1:1 |
| 性能优化 | 缩略图等比例压缩并落地磁盘缓存，界面不渲染原图，标签再多也不掉帧 |
| 健壮性 | 图片缺失显示灰色占位；数据文件损坏自动备份并重建；全程控制台日志可追溯 |

## 界面布局

```
┌──────────────┬────────────────────────────────┬──────────────┐
│  文件树       │  5 套互斥预设（单选）           │  标签仓库     │
│  （左侧）     │  标签组工作区                   │  （右侧）     │
│              │  中心大图预览（单击图片）        │  备注输入     │
│              │  命名预览 + 一键命名            │  新建 / 选择  │
└──────────────┴────────────────────────────────┴──────────────┘
```

- **左栏**：本机盘符文件树，图片格式高亮识别，启动自动定位上次打开的文件夹。
- **中栏**：预设切换栏 + 标签组 + 单击大图预览 + 命名预览与一键命名。
- **右栏**：标签仓库，横向换行、纵向滚动；单击标签回填备注，可编辑后保存。

## 环境要求

- Windows（文件树、任务栏图标等功能针对 Windows 设计）
- Python 3.8 及以上（开发环境为 Python 3.10）
- 依赖：`Pillow`（可选，但强烈建议安装）

> 不安装 Pillow 也能启动：tkinter 原生解码仅支持 png / gif 等格式，jpg / bmp / webp 会显示占位图。

## 安装与运行

```bash
# 1. 获取代码
git clone <本仓库地址>
cd 图片标签命名系统

# 2. 安装依赖（可选但推荐）
pip install -r requirements.txt

# 3. 启动
```

## 快速上手

1. **定位图片**：左侧文件树展开到目标文件夹，单击图片可在中部直接看大图。
2. **创建标签**：
   - 在文件树中选中一张或多张图片 → 点击右栏【＋ 从文件树新建图片标签】；
   - 或先在右栏备注框输入文字 → 点击【选择图片】批量导入。
3. **编排分组**：点击【＋ 新建组】建立标签组，把仓库中的标签拖进组；组内左右拖动调整顺序。
4. **选择组合**：单击组内标签进行选中 / 取消，底部命名预览实时更新。
5. **一键命名**：在文件树中选中目标图片 → 点击【一键命名】，磁盘文件即刻改名。

> 选中状态、分组顺序、当前预设、上次打开的文件夹都会随数据自动保存，下次启动原样还原。

## 命名规则

命名串由三部分组成，规则固定、结果可预期：

```
组从上到下 → 组内从左到右 → 下划线连接 → 可选末尾时间戳
```

- **内容取备注**：标签备注优先；备注为空时自动取图片文件名（去掉扩展名）。
- **时间戳**：默认勾选「添加时间戳」，格式为 `yyyyMMddHHmm`，取消勾选则只保留标签内容。
- **多文件命名**：第一个文件使用基准名，其余依次为 `基准名 (2)`、`基准名 (3)`……
- **非法字符处理**：`\ / : * ? " < > |` 等 Windows 非法字符替换为 `_`；命中系统保留名自动加前缀；结果为空时使用「未命名」。

示例：

```
图纸A_零件B_202610211035.jpg
```

## 数据文件

所有数据保存在程序同目录的 `tag_data.json`，结构概要：

```json
{
  "version": 2,
  "active_preset": 0,
  "last_dir": "D:/pic",
  "tags": [
    { "tag_id": "t001", "img_path": "D:/pic/01.png", "remark": "图纸A", "created_at": "..." }
  ],
  "presets": [
    {
      "preset_id": "p01",
      "name": "预设1",
      "groups": [
        { "group_id": "g001", "name": "标签组 1", "tag_ids": ["t001"], "selected_ids": ["t001"] }
      ]
    }
  ]
}
```

- 只保存**图片绝对路径与备注文字**，不保存图片本身，文件体积极小。
- 标签全局共享，分组与顺序归属各自的预设。
- 文件不存在时首次启动自动创建；解析失败会备份为 `tag_data.json.broken_<时间戳>` 并按默认数据重建。

## 关于 assets 目录

`assets/`（应用图标 `app_icon.ico` / `app_icon.png`）未纳入版本库：

- 缺失时程序**仍可正常运行**，仅窗口与任务栏无自定义图标；
- 如需恢复图标，在项目根目录新建 `assets/` 并放入同名图标文件即可。
- 配置中的 `resource_path()` 同时兼容源码运行与 PyInstaller 打包后的临时解包目录，便于后续打包分发。

## 技术栈

- **GUI**：Python 标准库 `tkinter` / `ttk`（`clam` 主题 + 自定义配色与字体）
- **图片处理**：`Pillow`（等比缩略、格式兼容），缺失时回退 tkinter 原生解码
- **数据存储**：JSON 单文件，无数据库依赖
- **编码规范**：类型注解 + 模块化拆分 + 全程 `logging` 日志
